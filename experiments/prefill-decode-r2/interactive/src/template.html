Many requests side by side

A server usually runs several requests together (batching). Each row is one request. Each column is one trip through the model. The number is how many positions that trip processes for that request.

These are logical counts of positions, not GPU cores and not time. Which part limits speed depends on prompt length, batch size, context length, the model and the hardware; nothing here was measured.

What one layer does, in toy numbers

Toy model: 2 layers, each position is a list of just 2 numbers, weights declared in the source. Each layer: attention (look back and mix), then a feed-forward network (rework each position on its own). Pick which position to follow:

Attention, computed

Layer 1. Score = query · key ÷ √2. Masked keys get no score. Softmax turns scores into weights that add up to 1; the output is the weighted sum of values. Edit the query or the mask and every number below is recomputed.
