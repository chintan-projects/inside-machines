# Prefill versus decode, revision 2
Status: draft for review. Authoring direction: Claude; logical computation visuals; Studio/ManimGL video; ElevenLabs v4.
Audience: the owner and curious adult beginners who have watched AI text stream but cannot trace one request. Starting level is inferred, not learner-tested.
Question: Why can known prompt positions be processed together while an ordinary autoregressive answer is built one new token at a time?
Outcome: Trace The / sky / is → blue → and, distinguish picked from processed, explain which computation the KV cache saves, predict the effect of turning it off.
Hypothesis: Showing exactly the same running token/state in input, cache and next-token selection lets an unfamiliar viewer explain the dependency and predict that disabling caching adds recomputation without changing the deterministic toy's output.
Core boundary: ordinary causal decoder-only full-attention Transformer, weights already resident, one request, exact toy arithmetic. No real-model benchmark, GPU-core count or absolute latency promise. Token pieces and scores illustrative.
Core causal spine: text→token positions/representations→causal attention plus feature transformations through layers→last-position vocabulary scores→decoding choice→first token blue, still unprocessed→blue becomes next input, current K/V joins allowed previous K/V→scores choose and→repeat.
The cache saves prior K/V computation, not all old attention work, model weights or answers. Same-layer K/V is derived before attention uses it; each layer has its own entries. Last picked token is not cached until processed. Current token attends to itself and allowed history.
Core uses one focused mechanism; optional depth covers batching/workload-dependent bottlenecks and a fully computed small attention example. Preserve baseline no-cache versus cached equivalence under exact toy rules, no actual-model invariance claim.
Controls: cache on/off changes recomputation, reused-state views and counts, preserves deterministic answer. Depth query/mask controls change actual computed softmax/weighted sum. Batching insight changes independent request lanes; do not label lanes as GPU core counts or timings.
Prediction: Can a GPU choose both unknown answer tokens in one ordinary generation pass? Hold answer until explained; skipping prediction must not block the core.
Transfer: A DIFFERENT request has SIX prompt tokens, already processed with its first answer selected. Cache is turned off before its second selection. What must be recalculated? Must the exact deterministic answer change? Six old positions plus one new position in two layers make 14 pairs instead of 2. Score 2 for both prior position K/V recomputation and unchanged deterministic next-token rule; 1 for only one; 0 for answer-cache/GPU-sequential misconception.
