GPU S3 input-supply model, artwork, narration and assessments in a new immutable
publication candidate. It is an optional insight, not a new complete GPU core.

Outcome: explain why an available slot may wait and predict whether adding empty
slots supplies missing data. Hypothesis: four of five initially unfamiliar
learners score2 on both causal explanation and changed-situation transfer before
hints. This is unmeasured; no release approval is recorded.

Grant: retain the same eight inputs and four slots while changing data readiness.
Feynman: identify the missing input before introducing performance terminology.
Veritasium: predict whether free slots guarantee useful work, then change supply.
Anatomy: this is a truthful logical representation, not a physical cutaway or die
layout. The shared player, state rules and native renderer carry every output.

Claims use the existing NVIDIA Programming Model §§1.2.1–1.2.3 source and its
declared CUDA/example limits. Ready-input dependence and supply constraints are
bounded inferences; the exact one/four-input, four-slot, eight-job arithmetic is

The 1.5-second animation round is presentation timing, not a clock or benchmark.

Core components: input memory → available calculation slots → stored outputs.
Each input0–7 produces input+1. Supply occurs before calculation in each ideal
round. Both comparisons keep inputs, operation and capacity fixed. At the14.5s
checkpoint, one-per-round has three stored results and one working job; four-per-
round has all eight results and now-idle slots. Source-bound tests must verify
those states. Cue order guides attention, not a universal hardware schedule.

Transfer: adding four slots while still supplying one input per round leaves
that declared supply limit unchanged. Score0 names parts; score1 identifies a
waiting input without tracing the changed condition; score2 connects data
readiness to useful execution and states the toy model's limits.
