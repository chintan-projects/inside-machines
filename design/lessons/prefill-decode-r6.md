# Prefill/decode R6: follow the computation before naming it

Question: why must a selected piece still be processed before the following choice,
and what earlier work can a separate cache at each layer save?

The learner assumption is basic arithmetic and no transformer vocabulary. Success
means explaining the causal chain and transferring it to thirteen old pieces plus
one unprocessed choice, and to an edit earlier in the text. The rubric was written
before fresh readers saw either question. This local experiment does not update or
approve the hosted catalog.

## Representation and limits

R6 uses a declared structural teaching calculator. It keeps the same The / sky / is
→ blue → and example, two causal layers and distinct per-layer preparation. Query
is half the layer input, key one quarter, value 0.8 times it. A match is query times
source key; its positive part plus one is a relative sharing amount. Divide each
amount by their total, apply those fractions to source values and add the reading
to the layer input. The local adjustment is half the mixed number's positive part;
add it back to the original mixed number to finish the layer.

This sharing rule differs from standard transformer softmax. It teaches the same
input-dependency and prefix-reuse argument, with different numbers. It is not a
trained model, a disclosure of GPT's internals, a quality prediction or a hardware
benchmark. It omits vector geometry, positional encoding, normalization and a real
vocabulary. R4/R5 remain held; their old findings were not waived. No training ran.

## Teaching decisions

Feynman's plain causal language means doing a concrete job before naming it. The
first layer's reading and update are completed before query/key names are attached
to the already-used numbers. Source preparation stays separate from a completed
layer result. A copied number is shown separately from the original before the
positive-part rule and final addition.

Purposeful visual reasoning means that operands stay on one diagram while a
multi-input calculation develops. Reached operations reveal their values; future
operation labels stay hidden. The source's reading value remains visibly separate
from its comparison number. The naming recap preserves the finished result and
shows only its completed reading inputs, without reopening a processing pass.

Prediction addresses a concrete misconception: after appending blue, would
recomputing the earlier is result change it? The proof follows unchanged sources,
inputs, layer-one results, layer-two inputs and saved preparation. Scoring the old
result again repeats blue; processing blue produces the following choice.

The replay asks its question before rewinding. Its baseline retains text and fixed
rules only, without old keys/values or finished working numbers. Rebuilding an upper
layer's entry therefore requires reconstructing its input. Counts describe new
key/value preparations at each layer, not elapsed time or all arithmetic.
