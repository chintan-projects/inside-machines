## Decision and implementation

and CE traceability. ADR 0004 and AGENTS make completeness primary: core must trace

Creator guidance remains a design reference, not the product promise or a quality score.

Four local nodes share one navigator/player: an 88-second complete pixel story;
the preserved 42-second independent/chain insight; 60-second data-supply comparison;
and a 76-second exact 2×2 matrix explanation. The matrix explicitly rearranges the
original add-one picture's first four results. Data comparison explicitly resets
its inputs between runs. Numerical outputs come from pure trusted rules. Times,
four slots and rounds are illustrative, not GPU benchmarks or die layout.

The portable `learning-path-1` JSON envelope resolves only trusted lesson IDs.
Python and TypeScript validate the actual same manifest; both reject unknown
versions/references, cycles, unreachable nodes and executable fields. A vacuum
fixture demonstrates structural reuse, not a new physical lesson. Shared geometry
is extracted without changing the original path rule or saved vacuum artifact.

The provider-neutral path planner and node authoring helper use existing evidence,
concept guidance and lesson schema. Node prompts receive the root question, shared
example, objective and prerequisites. Author recovery fingerprints include the new
instructions. Helpers prepare requests; they do not dispatch paid work. There is
no new gateway, queue, production endpoint or automatic arbitrary-topic generation.
Current detailed views are authored trusted adapters; prompt/schema tests do not
prove that a model can reproduce their factual or visual quality unattended.

The navigator preserves mounted node state/optional answers in ephemeral memory,
pauses before switching and restores the saved scene without autoplay. Mute follows
the learner across nodes. The input searches reviewed saved-question aliases; vague
“dive deeper” uses the current node's recommendation. Unknown/ambiguous questions
state missing coverage rather than pretending an AI response exists.

## Three bounded craft rounds

1. Utility/hierarchy: replace the narrow principle demo as the entry with the full
   causal spine. Separate the optional questions and preserve a visible return.
   Retain the physical board; computational views are explicitly logical.
2. Usability/visible consequences: remove empty advanced controls, reveal the scene
   after changing a control, make instruction/weight changes immediately inspectable,
   stop manual comparisons before leaving their result, and distinguish completed
   work from missing-input waiting. Request/input copies follow their actual bent
   paths; stable DOM nodes update in place. No real hardware travel time is implied.
3. Responsive/accessibility: phone renders exposed white Unmute text on transparent
   paper. Fixed the pressed background; computed white on rgb(49,106,87) observed.
   Darkened text on middle-gray pixels; all supported brightness pairs pass 4.5:1.
   New logical labels measure at least 14.23px at 390px; checked program/matrix
   labels stay within their canvas at 390/768/1280 widths with no horizontal overflow.
   Desktop figures also fit the expanded navigation more comfortably without
   shrinking phone labels. Screen-reader summaries expose current operands/results without revealing hidden
   outputs. These are viewport/agent checks, not actual-phone or VoiceOver approval.

Agent rubric, inferred: utility 4/5 (complete spine at the declared example scope),
usability 4/5 (branch/return/controls work), desirability 3/5 (logical views remain
simpler than the hardware art), surprise 3/5 (one changed weight exposes an entire
output column's dependence). These judgments are not an owner or learner pass.
